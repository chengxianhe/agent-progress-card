# 手机选项与系统审批分流

2026-11-12，用户反馈：与普通看板选项同时出现时，微信带编号回复未能继续执行，随后显示过期。
只读核对实际中转状态及源码，确认以下问题：通知使用“选项号”占位词，解析却只接受数字在前；
带占位词、编号在前或小写 a 的回复可能被当作普通聊天。历史已关闭请求也可能参与冲突判断。
本记录仅保留问题模式，不记录本人原始聊天、真实审批编号或命令内容。

## 统一信息结构

| 类型 | 手机通知与回复 |
|---|---|
| 系统命令、权限、表单等正式请求 | A 编号，通知附可直接复制的实际示例，如 `1 A0123456789` |
| 普通看板方案选择 | C 编号，如 `1 C0123456789`，仅回答对应看板问题 |
| 唯一已发送且无其他问题的正式请求 | 仍可只回复数字；多项或混合场景必须带编号 |

示例编号需要替换为实际通知中的编号。通知不再要求用户理解“选项号”这种占位词。
兼容已观察到的明确写法：`选项号 A编号 回复 1`、`选项号 A编号 1`、数字在前、编号大小写，
以及可唯一匹配的实际选项标签。匹配仍依据当前请求的实际选项与精确编号，不做近似猜测。
表单 JSON 原文保持不变，避免将用户填写内容误当作授权指令。

## 检查矩阵与边界

| 请求 | 当前处理 |
|---|---|
| `item/commandExecution/requestApproval` | 原顺序映射单次允许/拒绝/取消；未给可选列表时使用标准单次选项 |
| `item/permissions/requestApproval` | 只回显所申请的网络/文件系统权限，作用域为本轮，不扩大权限 |
| `item/fileChange/requestApproval` | 仅在完整、对应文件差异已取得时处理单次决定 |
| `mcpServer/elicitation/request` | 适配的工具调用授权与表单按结构响应，不返回持久授权 |
| `item/tool/requestUserInput` | 单题编号及多题/文字 JSON 按实际字段校验 |
| 命令附加权限/托管网络策略、会话写入根目录、网页登录或未知结构 | 明确通知限制，仍需原生或专用流程，不伪装成普通 Allow |

这里的沙盒权限是 Codex 正式请求；操作系统自身的安全授权弹窗不属于该协议。
达到 20 项活动请求上限时明确通知，不再静默忽略新请求。

## 生命周期与竞态

- 系统请求仍有效时才接受对应编号；已关闭与已过期分别说明，不再统一报告为泛泛的“编号不可用”。
- 已收到但待提交、已发出待回执、回执不确定分别提示；重复回复不重复提交。
- 电脑已经处理、断线、重启、旧消息早于请求或完整分段未送达时，不补交或自动换编号授权。
- 已关闭系统请求的历史不再阻挡当前普通看板选择；当前仍有系统请求时，裸数字保持歧义保护。
- 当前 A 请求与 C 选项可在手机分别作答，C 选择不批准系统权限，A 回复也不消费普通选项。
- 裸数字仍检查消息是否早于当前看板问题；存在待选问题时，越界数字在本地解释，不转成新任务。

## 回归证据

`test_mobile_selection_routing.py` 覆盖五类请求乘以五种数字写法、A/C 分流、历史关闭请求、
冲突裸数字、错误 C 编号、精确标签、重复回复、关闭与过期区分、可选决定列表缺失、
分段未送达、JSON 原文保持与请求上限。原有全部审批、权限、文件变更、MCP 和重启用例继续执行。
安装后追加回归复现并修复：收件时间曾覆盖消息发送时间，导致迟到裸数字可能误选新问题或新审批；
看板和系统请求的越界数字还可能转成新任务。收件现在保留微信消息时间，拒绝非有限/布尔时间戳，
普通选择在提交前核对时间和选项范围；增加五项行为测试。
升级前已有 inbox 行的原始发送时间无法还原，本次更新前核对待投递 inbox 为零；不伪造旧行时间。

安装恢复另发现旧中转持有的锁文件与磁盘路径的 inode 不一致。文件锁可用不足以证明旧进程已退出；
本次按精确绑定核对旧进程退出后，重启既有常驻项，并检查唯一新进程、新队列表结构和实时状态字段。
没有改动常驻安装器或以删除锁文件作为重启手段；锁文件被替换的来源尚未确定。

统一验收：`bash scripts/verify.sh`。最终实际结果与源码摘要保存在
`build/verification/wechat-queue-summary.json`，自动检查不代替手机端实际验收。
本轮不修改永久权限、模型配置或用户绑定，不替本人选择任何新的系统审批。
