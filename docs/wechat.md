# 本人微信连接

默认使用当前会话 relay。条件是小看板已绑定目标会话，Codex 客户端已打开该会话，
本机存在可用的控制 socket，微信账号支持 iLink/ClawBot 配对。此通道是实验性适配。

```bash
PYTHONPATH=src python3 -m agent_progress_wechat.relay \
  --state-dir "$PWD/runs/wechat" --thread-id THREAD_UUID
```

小看板“连接设置”显示二维码、配对码及连接状态。首次扫码后凭据保存在指定目录；
凭据有效时重启可继续使用。登录失效、服务已停止或连接异常时，可在小看板“连接设置”点击“重新扫码连接”；
旧监听会停止，旧凭据会先备份到本机私有状态目录，再在原状态目录显示新二维码。手机微信扫码确认后恢复当前会话转发。
若显示“微信回信上下文已过期”，先在扫码绑定的机器人会话发送“选项”或“进度”刷新回信上下文；
这与登录凭据失效是两种不同状态。程序不再假设回信上下文只有 90 秒有效期。
普通原生输入表单会作为只读通知同步；查看题目和选项后需回原客户端作答。
显式发布的看板选项仍支持微信编号与卡片按钮。
不要上传 `credentials.json`、`relay.sqlite3`、二维码或含真实消息的日志。

普通文本成为绑定会话的用户输入；忙碌时追加指令，空闲时开启该会话的下一轮。
不新建/分叉/恢复其他会话，不覆盖模型、工作区、沙箱或权限策略。命令审批须显式启用，见下文。
收到服务端回执只表示输入被接受，不代表任务完成。

发送后断线或回执丢失时记录“投递结果不确定”，不自动重发指令；未发送的任务可等待重连。
公开工作说明限频回传，最终回复立即排队；重启恢复的历史消息不自动补发。
结果沿用卡片的脱敏与长度限制，可能截断。通知以 30、60、120、240、300 秒的退避持续重试，旧版失败满 5 次的积压也可恢复；不承诺网络层恰好一次投递。
接口拒绝回信时，转发器保留通知并暂停发送 5 分钟后自动重试；新入站消息可立即唤醒。
在本人微信发“选项”后可直接取回当前待选问题；回复编号会送入已绑定的 Codex 会话，
收到投递回执后自动关闭选项。回执不确定时不会自动重发，也不接受重复编号，需先在桌面核对。
微信主动推送受回信上下文时效限制，卡片会保留待选问题，不会把“排队”显示为“送达”。

`选项`、`进度`、`结果`、`帮助`从本地记录回答，不额外调用模型。普通聊天和编号选择会产生会话的正常模型用量。
卡片里“停止同步”或命令行 Ctrl-C 停止转发，不取消 Codex 已接收并正在执行的任务。
电脑休眠、断网、客户端退出或绑定切换会影响连接；可显式安装[用户级常驻服务](wechat-resident.md)，但不能保证微信接口长期接受主动推送。

如启动失败，核对 thread UUID、卡片绑定和客户端运行状态；不要通过降低原会话权限限制解决连接问题。
扫码入口不可用以微信实际返回为准；不支持个人聊天列表、群消息、语音、图片和附件。

## 保留的独立只读模式

旧的独立执行器作为可选兼容入口保留，默认 README 不使用它。它不会续接现有会话：

```bash
bash desktop/build-wechat.sh
PYTHONPATH=src python3 -m agent_progress_wechat \
  --workspace /absolute/path/to/your/workspace --state-dir "$PWD/runs/wechat-legacy" \
  --window "$PWD/build/WeChatLogin"
```

此模式新建独立 Codex CLI 任务，使用只读沙箱和禁止提权策略；不应与当前会话 relay 混用状态目录。
只读沙箱限制写入，并不意味着只能读 workspace 内的文件。它仅供本人使用，不是接收陌生人任务的服务。

## 发送与提问同步修复（2026-11-11）

- 沿用消息编号去重与通知 `client_id`；新入站消息只唤醒未送达的通知，不重放已投递或投递不确定的任务。
- 旧请求失败时只失效它实际使用的上下文，防止并发入站刷新被覆盖。
- 原生提问只从绑定记录的白名单工具参数中提取公开题目和选项，限长并脱敏；最近 8 份通知独立保留，
  避免同次采集仅推最后一道题。每份最多展示 3 个问题、每题 5 个选项，超出时提示查看原客户端。
- 原生提问记录不代表仍待回答；工具回执 `accepted` 不代表用户已回答。没有可靠原生表单答复协议时，
  不把普通 `turn/steer` 冒充表单提交。正式命令审批走独立的显式启用通道，见下文。
- 微信 `ret=-2` 按暂时不可回信处理：全队列暂停 5 分钟后自动探测，新入站消息可提前恢复；
  不把该错误断言为确定的上下文过期，也不永久停等。补发成功后间隔 1 秒继续，避免瞬间刷出积压。
  [腾讯协议说明](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md)要求回信携带入站上下文，
  不提供本实现可依赖的 90 秒有效期保证。接口接受请求也不能证明手机已显示通知。

## 本人微信单次命令审批（实验性）

首次启用时，在原 relay 启动命令增加 `--remote-approvals`；设置保存在绑定账号和会话的
本机 relay 数据库中，重新扫码/重启沿用。关闭时以 `--no-remote-approvals` 重启同一 relay。
既有服务需先正常停止，不能并行启动两个监听。未显式启用的连接保持关闭。

- 收到「待授权 A…」后，检查完整命令、目录和原因，再按原生弹窗顺序展示编号；回复「选项号 A编号」。单项审批且没有普通选项时可只回数字。
- 「审批」查询当前编号并重新排队通知；单独数字只在唯一已通知审批且没有普通选项时生效；有歧义时必须带审批编号。
- 编号有效期 10 分钟，且只适用于当前账号、会话和连接。重启/断线/电脑端处理后失效。
- 只支持完整可展示的 command/humanCommand 单次命令审批。
  保留服务端 availableDecisions 顺序：accept/decline/cancel 按实际选项执行；长期规则和会话放行
  显示原位置并注明电脑端操作。cancel 会结束本轮，不能把“拒绝”悄悄换成 cancel。包含额外权限、专用网络授权、
  敏感内容、过长命令及其他审批类型时，保留电脑原生确认。不会在微信输出被隐藏的命令来请求批准。
- bridge 使用正式 JSON-RPC 响应，接收 `serverRequest/resolved`；关闭回执只说明请求已结束，
  不能判断手机与电脑谁先处理，也不证明命令成功。发送后断线或超时不自动重发决定。
- 启用后单独保持审批订阅连接：先核对原会话打开，再 `thread/resume` 同一个 ID，
  仅传 `threadId/excludeTurns`，不改模型/权限/工作区，不开启新轮次、不恢复已关闭的会话。
- 关闭整个微信同步会停止审批连接；电脑端始终可以处理。同一请求电脑先处理时，手机编号失效。
- 微信登录、回信窗口、电脑休眠等仍会影响送达；通知入队不等于手机显示。

协议依据：[OpenAI App Server Approvals](https://learn.chatgpt.com/docs/app-server#approvals)。
