# 全部消息恢复与手机请求覆盖

本轮由“二选项只能看不能选”和“重连刷出大量通知”扩展为同一条交互链的检查。
基线 `650a20e563fbceafdf5a7bc78792c01de65cf7b6`，原仓库工作区干净；在隔离副本实施，
不改主工程、不采集其他会话、不迁移账号或凭据。安装和真实手机验收单独确认。

## 统一不变量

- 所有出站类别使用同一个暂停规则，没有审批、原生提问、警告等“保护队列”豁免。
  断开后未送出正文清空并标记superseded，不冒充delivered；身份墓碑用于防止旧事件回放。
- 重新启动也暂停缓存回信上下文，新的本人消息恢复后只自动发一条当前摘要。
  同步游标、入站任务、有效请求与通知正文分开，丢弃通知不等于批准/取消请求或删除本人任务。
- 有效请求在本地状态中保留，按查询重建完整详情。“审批”每页最多5项，
  “审批 2”取第2页，“审批 A编号”只取该项；不一次重放全部审批。旧编号不延长有效期；同一连接确认仍在等待的请求，可在本人查询后换新编号，必须重新明确作答。
- 详情有分段时全部送出前不能使用数字或填写提交。刷新使用通知修订号，迟到回执不能标记新版已送达。
  完成回执只表示服务端关闭请求，执行成功另看任务结果；不确定结果不重发。
- API已接收的数据无法从本地撤回，也没有可靠的手机前台在线证明。
  该策略约束本地暂停/重启和后续发送，不能承诺撤销上游已接受的消息。

## 请求矩阵

对照本机 `codex-cli 0.167.2` 的 `app-server generate-json-schema`，有10类服务端请求。
官方入口：[App Server](https://learn.chatgpt.com/docs/app-server)。不是所有服务端请求都是可点击的用户弹窗。

| 来源 | 手机方式 | 约束/退路 |
|---|---|---|
| 助手显式方案选择 | C编号，卡片按钮/微信回复 | 原有接口兼容，投递为本人聊天 |
| 新的普通异步提问 | 自动生成C；单选按钮、多题/文字填写 | 仅明确工具名与完整可展示字段；新本人消息后转为记录；不声称代交原生表单 |
| 历史异步问题/无正式请求的同步表单 | 只读记录和明确说明 | 不重放历史、不伪造原生回执；结构不支持也提示 |
| `item/commandExecution/requestApproval` | A；按实际顺序选择单次决定 | 命令、终端输入、完整网络目标/环境分别展示；持久规则/会话放行不代答 |
| `item/fileChange/requestApproval` | A；对应完整差异 | 缺差异/会话写根目录授权需原客户端 |
| `item/permissions/requestApproval` | A；所列权限仅本轮 | 不增加权限，不隐含允许其他路径 |
| `item/tool/requestUserInput` | A；单题编号或多题/文字JSON | 非秘密、完整支持的字段/约束，逐字段校验 |
| `mcpServer/elicitation/request` | A；工具Allow/Cancel或受支持表单 | URL登录/秘密输入/不支持约束明确交还原客户端 |
| `execCommandApproval` | A；保留命令参数数组边界 | 使用旧协议实际decision结构，不将单次同意升级成长期规则 |
| `applyPatchApproval` | A；完整文件变化 | 拒绝grantRoot，拒绝缺内容/未知变更结构 |
| `item/tool/call` | 同会话时提示需原客户端处理 | 这是后台动态工具调用，不伪装成Allow弹窗或虚构工具结果 |
| `account/chatgptAuthTokens/refresh`、`attestation/generate` | 身份/全局能力，专用流程 | 不用微信选项代填认证/证明；无会话绑定不转发其参数 |
| 未知同会话审批 | 明确限制通知，可查询当前记录 | 不静默假成功，不靠选项文字猜授权类别 |
| 操作系统隐私权限/网站验证码 | 原客户端/设备处理 | 不属于该会话的App Server请求协议 |

普通问题的C聊天答复与正式A协议响应保持两个命名空间。对同步表单没有正式请求时，
仍不能保证用聊天答复解除原生等待；只能明确通知，不能声称所有宿主/系统弹窗均已适配。
来源内容有敏感字段、截断或未知结构时，不为扩大覆盖率隐藏限制。

## 状态与调度

- `delivery_policy.py`统一暂停、恢复水位与一次摘要，旧库增量迁移；不清空inbox、凭据和治理记录。
- `approval_notice.py`与`choice_notice.py`从当前状态生成按需完整分段，修订号隔离迟到回执。
- `inbound_dispatch.py`为本地查询/正式决定保留处理线程；普通任务20项与控制40项容量分开。
  dispatching只表示准备投递，重启可重新排队；sending之后不确定则不重发。
- WebSocket握手/帧按整体截止时间读，慢速字节不能延长总时长；持续事件流仍调度到审批提交/过期清理。
- 采集器只为新发生且完整的普通异步问题生成C，保留手动问题优先与绑定校验。
  并发手动发布不应让采集器报错；新本人消息后旧问题不再主动弹出，历史保留。

## 验证与交付

统一执行`bash scripts/verify.sh`，包含全部Python测试、两个原生入口构建与8组模型测试。
日志、源码指纹与退出码放在本机忽略的`build/verification/`。不把构建/模型测试称作真实窗口或手机验收。
新增测试覆盖全部通知类别突发、断开/重启/恢复、旧事件去重、请求按需分页、迟到回执、
控制容量/调度、慢速帧、持续事件、普通问题/文字多题、分段完整性、旧协议响应及原有隔离/隐私检查。
旧测试里“保护类消息离线保留”的断言按用户新要求更新；完整详情、会话隔离、明确本人决定和不确定不重发继续检查。

安装前需核对当前App与桥接进程，备份旧App及私有运行数据库，再受控重启既有常驻项；
启动会使旧A编号失效，新消息才恢复发送。不得删除锁文件充当停机证明。
安装后检查单一进程、实际加载新代码、队列不重放，并由本人进行一轮手机选择/查询。
未安装、未实测和未知结构明确列为限制，不在本机自动检查通过时宣布用户已验收。

知识沉淀：本次将机制与边界固化为代码/故障测试/本记录，不重复向主工程知识库提交应用层规则。

## 无人值守反向检查（2026-11-13）

以“本人只带手机，无法点击电脑”为失败场景，补查通信、任务、审批、采集和监督，不能只看进程活着。
本轮开始时原仓库已有上一轮未提交改动；保留该快照，在同一隔离副本继续，未替换运行中的App。

| 失败触发 | 发现与修复 | 仍须明确的边界 |
|---|---|---|
| 查询详情与断开同时发生 | 已复现暂停后刷新重建未发正文；两个详情发布器均先检查统一暂停状态 | API已接受的消息无法撤回 |
| 超过10分钟才回复授权 | 已复现服务端仍等待、手机却查不到；分离请求存活与编号时效，本人查询才换新码 | 仅同一存活连接；旧码、旧回复无效，不自动沿用决定 |
| 编号过期后电脑处理/连接断开 | resolved关闭同一不可变请求键；断开清除server_live；测试保证不能复活 | 不确定提交不重试，新连接无权伪造旧请求 |
| 任务后端启动时不可用 | 取消收件对后端启动成功的依赖，手机本地查询继续 | 正常任务投递与审批订阅仍验证原会话，不自动打开关闭会话 |
| DNS/TLS/慢速响应卡住 | 微信HTTP操作隔离在固定stdlib子进程，整体截止时结束并回收；凭据仅走stdin | 默认收件总预算40秒、发件20秒，OS调度并非硬实时；不保证上游可用性 |
| 进程活着但工作线程卡住 | 内部进展心跳120秒停滞触发受控退出；既有监督仅管理自己启动的Popen子进程，必要时terminate/kill | 手动停止、绑定改变、登录过期仍优先；不杀其他服务或自动安装自启 |
| 电脑休眠/时钟跳变 | 检测大于30秒跳变，给工作线程20秒刷新宽限，避免醒来立即误判 | 睡眠/关机期间无法通信，实际长期睡眠待实机验 |
| 看板仍显示执行中 | “诊断／出门检查”分别报告后端、审批、采集心跳和监督证据；进度附当前异常 | 缺少新证据明确提示，不拿最后一次任务状态当在线证明 |
| 后端在等授权但手机没有请求 | 诊断明确报告订阅/重发缺口，不声称当前无事 | 后端未重新发出正式请求时，手机查询不能补造其ID/响应 |

故障测试覆盖真实挂起子进程的截止终止、跨进程错误类型、后端不可用时实际收件/本地诊断、
编号轮换/迟到回复/过期后关闭、断开与不确定结果、暂停刷新竞争、监督身份/心跳、休眠宽限。
测试账号/进程均为隔离合成数据；不发送真实微信、不操作实际常驻进程。

“出门检查”本身可回复只能证明当时本人的往返链路可用。后续电脑掉线、微信登录失效，
同一个已断的通道无法通知或自己扫码恢复；要消除必须回家的风险，需要用户另行选择并配置备用入口。
不擅自安装远程桌面、改变系统睡眠/安全策略或转发认证秘密。

后续本机记录见忽略的 `build/verification/outside-recovery-summary.json`：已安装，进程/采集/监督
检查及桌面选项显示通过；本人手机反馈“仅电脑显示，微信没有收到”，当时仍待新的本人回信上下文。
手机详情、编号回复、诊断与重连无积压仍待实际验收，不沿用早期“待安装”状态或宣称手机已通过。
