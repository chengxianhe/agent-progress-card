# 本人微信单次命令审批

审批连接和普通聊天投递分别处理：先核对原绑定会话处于打开状态，再通过 `thread/resume`
订阅同一会话，仅传 `threadId/excludeTurns`，不覆盖权限、工作区或模型配置，不创建新会话。

收到正式 `item/commandExecution/requestApproval` 后，按 `availableDecisions` 原顺序展示。
不假定每个客户端都提供 `decline`；`cancel` 会结束本轮，需明确展示，不用它偷偷替代拒绝。
长期规则和会话放行保留原位置，标明需电脑操作；不能完整展示的命令或额外权限仍走原生入口。

本人明确回复有效编号后，桥接提交对应 JSON-RPC 单次决定，并等待 `serverRequest/resolved`。
该回执也可能来自电脑端处理或请求取消，因此只能说明请求已关闭；执行结果单独核对。
断线后的未确认提交不自动重发，重连后的新请求生成新编号。

状态记录绑定账号、会话和连接，包含到期时间；重复、过期、跨会话和未通知的数字不触发审批。
多个审批或同时有普通选项时必须携带完整审批编号。
数据库以增量 schema 变更保留旧记录，不清空任务或凭据。

## 验证范围

- 自动测试覆盖本人/群聊过滤、跨会话隔离、重复回复、电脑端关闭竞争、重启与断线失效、
  敏感或不完整命令回退、严格单次决定、编号顺序和审批通知优先级。
- 本机实测完成：本人微信选择单次允许，桥接记录决定，服务端关闭请求，测试命令退出码为 0。
- 本机确认长期允许项只提示电脑端操作，不提交长期规则。
- 未做真实“取消并结束本轮”的手机验收；未保证长期无人交互推送。
- 未将真实账号、审批编号、消息原文、会话记录或本机验证路径放入公开源码。

协议依据：[OpenAI App Server Approvals](https://learn.chatgpt.com/docs/app-server#approvals)。

通知采用精简格式：具体命令、目录、原因、原顺序选项与一行回复说明。
不截断实际命令、不把摘要当作完整授权正文。

## 无法在微信处理时

通知会说明具体原因，不回显被拦截的敏感内容。当前命令正文上限为 1,400 字符，
目录 300 字符，原因 400 字符；超过上限、敏感内容、控制字符、缺少字段、
额外权限或未支持的选项都需要电脑处理。此类通知没有可回复的有效授权编号。
长命令分段展示与手机确认尚未实现，不能把这类通知当作已支持微信授权。
